## 3. Critical residual design issues

**A. Cryptographic truth vs signer authority.** A genuine Ed25519 signature proves signing key possession and signed-byte integrity, **not the real-world truth**, legal execution or verified provenance of a document's claim. Synthetic intake/review actor permissions are not external, independently constituted Foundation governance; no real signers appointed, documents independently authenticated, or agency-recognized record included.

**B. Storage generation and object custody.** The v1 attestation signs document ref, content hash, timestamp, binding and signer ID but **not** cloud project, storage bucket, object key, generation or custody policy. The R15 bridge explicitly found that a new generation with identical content passed the R14 verifier. A v2 receipt needs versioned project/bucket/key/generation binding and a reviewed migration/revocation plan. Signing an immutable object ID cannot substitute for verified Storage IAM and actual retention controls.

**C. Distributed transaction and recovery.** The standalone prototype follows `sign → sealCas → recheck → publish`; the signing call precedes sealing to prevent a signer outage from creating an unpublished sealed object. **Even so, the steps are NOT atomic across cloud Storage, signer and Firestore**. If publication fails or post-seal verification fails, a source may be sealed but not published. Implement an idempotent durable state machine, outbox/compensation, lease/recovery and replay/race tests under official SDK.

**D. No actual Firebase/Functions security proof.** The container had Node 22.16, Java 21 and TypeScript 5.8.3, but not official Firebase CLI/Firestore Emulator JAR or Firebase SDK dependencies; DNS resolution for GitHub and npm registry failed. Thus there is **no official emulator, live Functions, App Check, Firestore/Storage Rules, IAM, tenant-purpose, browser/device or deployment proof**. The source-level Firestore Rules still broadly permit any active Foundation staff role to read a number of sensitive grant and document collections. No real UrAi memory, RuAi clinician/patient record, donor banking or protected legal data were used.
