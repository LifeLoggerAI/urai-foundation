# URAI Accessibility and Cognitive Safety Checklist

## Accessibility target

URAI should aim for WCAG-aligned accessibility where feasible, plus cognitive accessibility and low-stimulation design for users with disability access needs.

## Visual

- high contrast mode
- readable typography
- scalable text
- reduced visual clutter
- color is never the only meaning carrier
- clear focus indicators
- low-stimulation palette option

## Motion

- reduced motion mode
- no mandatory parallax
- no flashing
- no rapid transitions
- no forced camera motion
- pause/stop controls for animations

## Navigation

- keyboard navigation
- screen reader labels
- predictable navigation
- skip links or bypass blocks
- clear page titles
- consistent buttons
- visible back and exit controls
- no keyboard traps

## Cognitive

- plain-language mode
- one-step-at-a-time mode
- clear next action
- save progress automatically
- no shame language
- no urgency theater
- no streak addiction
- no overwhelming dashboards
- no endless feeds
- no surprise intense content

## Audio and video

- captions
- transcripts
- no required audio-only instructions
- volume control
- mute option
- low/no background audio option

## Forms and authentication

- clear labels
- error prevention
- error suggestions
- accessible authentication
- enough time
- timeout warning
- easy recovery

## Sensitive content

- preview before playback
- blur, lock, or skip
- no autoplay of intense material
- exit controls
- delete and redact options
- private mode
- support resources when needed
